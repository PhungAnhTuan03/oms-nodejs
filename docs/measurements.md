# Measurements

Measured in a Linux cloud lab (PostgreSQL 16, Redis 7, Node 22), 200,006 orders / 400,067 order items
generated by `scripts/fake-orders.sql`.

## Oversell test (scripts/oversell-test.ts)

100 concurrent `POST /api/orders` for a variant with 1 item left:

```
Gửi 100 request trong 311 ms
201 (thành công): 1
409 (hết hàng):   99
Khác:             0
```

Stock afterwards: `available = 0`, order count +1.

## Index impact (EXPLAIN ANALYZE)

| Query | Before index | After index |
|---|---|---|
| Order items by `orderId` | 17.5 ms (Parallel Seq Scan) | 0.04 ms (Index Scan using `OrderItem_orderId_idx`) |
| Top products, last 7 days | 54.6 ms | 58.5 ms (planner still picks Seq Scan on `OrderItem`) |

The second row is expected: the join touches every order item from the last 7 days, so a
sequential scan is cheaper than many index lookups. The planner decides from table statistics.
